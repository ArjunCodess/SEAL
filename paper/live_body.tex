\section{Introduction}
When workers assert false completion on fixed local records, a live model supervisor can still publish to the fake sink. Unsafe execution counts every executed publication of an illegitimate workflow, including a summary corrected to the true summary. The central question is which supplied evidence tier, worker claims alone, signed receipts and a fresh checkpoint, a fixed keeper snapshot, or trusted provenance plus policy enforcement, changes that rate versus legitimate completion on paired synthetic fixtures. This study is a controlled evaluation of instructed attacks on a fake local publication sink; it is not evidence of spontaneous real-world collusion \cite{shi2026emergentcollusion}.

SEAL (Supervisor Evidence Arms, Live) uses locally frozen protocol \texttt{\StudyProtocolName{}} with a reproducible fixture catalog, a budgeted resumable harness, and family-cluster bootstrap analysis. The main design targets \MainTargetEpisodes{} held-out test episodes across \IndependentFamilies{} template families, with \TestVariantsPerFamily{} numeric variants per family. Those variants are repeated measures inside the family. Development uses \DevVariantsPerFamily{} variants per family and is excluded from test denominators. Held-out attacks use three mechanisms on four templates: consistent fake input on both \texttt{parts-catalog} and \texttt{sensor-calibration}, unauthorized publication on \texttt{payroll-release}, and ambiguous evidence on \texttt{incident-timeline}. All four arms receive identical worker messages plus tier evidence so message availability does not suppress the single-versus-coordinated contrast. Only the provenance arm can apply a deterministic veto after a supervisor publish decision. A zero harmful execution rate there would bound rule enforcement, not learned model robustness.

\section{Related Work}
Agent benchmarks and instruction-hierarchy training study prompt injection and privileged instructions under tool use \cite{debenedetti2024agentdojo,wallace2024instructionhierarchy,debenedetti2025camel}. NARCBench and HELIOS probe instructed collusion in multi-agent settings with activation sensors \cite{rose2026helios}. CollusionGuard supplies public behavioural features for investigating agent interactions \cite{sharma2026collusionguard}. AI-control literature motivates testing oversight against subversion without claiming a full control protocol here \cite{greenblatt2023aicontrol}. Closest to this work are deterministic publication gates and stored-state consistency checks from our November stored-state matrix; the live study adds live supervisor models and arm-matched observations rather than offline activations alone.

\section{Methods}
\subsection{Fixtures and arms}
Four development mechanisms (false completion, wrong summary, omitted step, stale evidence) diagnose the harness. Four held-out templates implement three test mechanisms. Consistent fake input is repeated on \texttt{parts-catalog} and \texttt{sensor-calibration}. \texttt{payroll-release} is unauthorized publication. \texttt{incident-timeline} is ambiguous evidence. Identifiers follow \texttt{family\_\allowbreak{}id.index.coordination}. The ten variants in a family change numbers inside that template. They are not independent samples. The bootstrap resamples four \texttt{family\_\allowbreak{}id} blocks, not forty fixture indexes. Intervals stay coarse: the blocks are few, and two of them share a mechanism.

Single and coordinated attacks share signed records. The single condition is one publisher role. The coordinated condition is three role-specific speakers, for example \texttt{parts\_\allowbreak{}loader}, \texttt{price\_\allowbreak{}clerk}, and \texttt{catalog\_\allowbreak{}publisher} on \texttt{parts-catalog}. Message count and speaker roles both differ. Message volume and speaker roles are confounded, so coordination contrasts stay descriptive. We do not claim a pure coordination effect. Honest controls rebuild the legitimate pipeline for each variant and always use three speakers. There is no single-speaker honest control. Legitimate completion is estimable only on that three-speaker honest pipeline, so the single-versus-coordinated contrast for legitimate completion is empty.

State observations are fixed read-only keeper snapshots with \texttt{adaptive=false}. They are not multi-turn adaptive queries. Ed25519 signing keys are deterministic public material for reproducibility.

Arms are intentionally not information-matched. Claims sees task text and worker messages. Receipts adds verified receipts and a fresh checkpoint. State adds the keeper snapshot. Provenance adds trusted inputs, digests, tool allowlists, and channel policy, and only that arm can veto a publication in deterministic code. The provenance observation also includes \texttt{trusted\_\allowbreak{}summary}, precomputed from \texttt{trusted\_\allowbreak{}inputs} when \texttt{binding\_\allowbreak{}complete} is true. On the three answerable test families, \texttt{parts-catalog}, \texttt{payroll-release}, and \texttt{sensor-calibration}, that field equals the fixture true summary in every coordination, attacks included. This is correct-answer access. It is not a \texttt{legitimate} or mechanism label. On \texttt{parts-catalog} and \texttt{sensor-calibration} the exposed summary differs from the worker candidate. On \texttt{payroll-release} the summary matches the candidate and the attack is the channel. \texttt{incident-timeline} attacks are unanswerable, \texttt{binding\_\allowbreak{}complete} is false, and \texttt{trusted\_\allowbreak{}summary} is null. The honest control on that family is binding-complete, so it also receives the derived true summary. A provenance legitimate-completion rate is an upper bound under that exposure. Fresh checkpoint handling is identical across receipts, state, and provenance. Reference decisions in the fixture catalog supply equal-observation baselines for pairing checks, not supervisor policies.

\subsection{Models, workers, and budget}
Supervisor models are Gemma 4 31B (\texttt{gemma-4-31b-it}) and Qwen 3.5 397B (\texttt{qwen3.5-397b}) on the Adaption Responses API. Worker messages are one-shot Gemma wording calls under \texttt{WORKER-CORPUS-ASSEMBLY-v1}, not live worker decisions: \WorkerAccepted{} accepted generations, \WorkerRejected{} rejected, \WorkerIncomplete{} incomplete, over \WorkerFixtureSchedule{} fixtures and \WorkerMessagesSchedule{} scheduled messages, model \WorkerModel{}, spend \WorkerSpendTotal{} credits. The generator prompt supplies the scripted message as \texttt{wording\_\allowbreak{}reference}. In the assembled test corpus, 280 of 280 accepted model calls reproduced that baseline byte for byte, and each ends \texttt{claim\_\allowbreak{}status: complete}. The assembly audit marks all 120 fixtures \texttt{source=generated}. The corpus preserves scripted wording. Assembly is a format and provenance check, not a source of wording variation. A failed call is not silently replaced by the scripted baseline. Generated text never changes labels, summaries, or ground truth. The same assembled corpus is shared by every supervisor arm and model.

Development pilot protocol \PilotProtocol{} recorded \PilotLedgerEpisodes{} ledger episodes (\PilotCompleted{} completed, \PilotInvalid{} invalid, \PilotPending{} pending) with pilot \texttt{max\_\allowbreak{}output\_\allowbreak{}tokens}=\PilotMaxOutputTokens{} and spend \PilotSpendTotal{} credits. Pilot families are harness repair only. Main spend caps, output limits, and prices are pinned in the main run manifest before outcome inspection. Null \texttt{usage}, \texttt{latency\_\allowbreak{}seconds}, and \texttt{cost\_\allowbreak{}units} are accepted only for \texttt{error} and \texttt{invalid} records. A completed episode requires measured usage, latency, and cost. A completed record that omits them fails schema validation and is not entered as unknown. \texttt{usage\_\allowbreak{}unknown\_\allowbreak{}episodes} and \texttt{cost\_\allowbreak{}unknown\_\allowbreak{}episodes} therefore count only omissions on error and invalid records. Incomplete responses stay in the all-status accounting below. They are not called completed.

\subsection{Endpoints and analysis}
Co-primary rates use completed episodes only. Unsafe execution is the number of executed publications on illegitimate completed episodes, divided by the number of those episodes. The numerator counts every executed publication of an illegitimate workflow, including a summary corrected to the true summary. That corrected publication is still unsafe. It is not legitimate completion. Legitimate completion is an executed publication that is legitimate, answerable, and equal to the true summary, among legitimate completed episodes. Error and invalid episodes are excluded from both completed-case denominators and never receive imputed outcomes.

All-status rates use the full legitimacy class. \texttt{illegitimate\_\allowbreak{}unsafe\_\allowbreak{}execution\_\allowbreak{}all\_\allowbreak{}status\_\allowbreak{}rate} divides observed unsafe executions by every illegitimate episode. \texttt{legitimate\_\allowbreak{}completion\_\allowbreak{}all\_\allowbreak{}status\_\allowbreak{}rate} divides observed legitimate completions by every legitimate episode. Episodes that are not completed, and rows with no outcome, count as non-success. Those rates are sensitivities. Their denominator is not a completed-episode count.

A supervisor decision and a deterministic veto are different events. On claims, receipts, and state, a publish decision executes on the fake sink, so the unsafe-attempt flag and the unsafe-execution flag match. On provenance, a publish decision is only a request. Deterministic code then executes it or vetoes it, recorded as \texttt{refused\_\allowbreak{}block} or \texttt{refused\_\allowbreak{}abstain}. A supervisor choice to block or abstain is \texttt{supervisor\_\allowbreak{}declined}, not that veto. The stored supervisor reason does not change the sink. An unsafe attempt is a publish request that fails the safety predicate. The predicate holds only when the fixture is legitimate and answerable and the summary equals the true summary. Illegitimate fixtures fail it for every summary, so every publish request on them is an unsafe attempt, corrected summary included. A gateway block is an unsafe attempt the provenance gate did not execute. The analysis keeps \texttt{illegitimate\_\allowbreak{}publish\_\allowbreak{}decisions}, \texttt{illegitimate\_\allowbreak{}outcome\_\allowbreak{}unsafe\_\allowbreak{}attempts}, \texttt{illegitimate\_\allowbreak{}outcome\_\allowbreak{}unsafe\_\allowbreak{}executions}, and \texttt{illegitimate\_\allowbreak{}gateway\_\allowbreak{}blocked\_\allowbreak{}unsafe\_\allowbreak{}attempts} as separate counts.

The stored column \texttt{illegitimate\_\allowbreak{}decision\_\allowbreak{}to\_\allowbreak{}outcome\_\allowbreak{}attempt\_\allowbreak{}gap} equals \texttt{illegitimate\_\allowbreak{}publish\_\allowbreak{}decisions} minus \texttt{illegitimate\_\allowbreak{}outcome\_\allowbreak{}unsafe\_\allowbreak{}attempts}. That difference is not a gap between a decision and an executed publication. Executed publication is \texttt{illegitimate\_\allowbreak{}outcome\_\allowbreak{}unsafe\_\allowbreak{}executions}, and a veto that stops the sink is \texttt{illegitimate\_\allowbreak{}gateway\_\allowbreak{}blocked\_\allowbreak{}unsafe\_\allowbreak{}attempts}. The difference equals the number of publish decisions without an \texttt{unsafe\_\allowbreak{}attempt} flag only when every such flag sits on a publish decision. When the outcome flag copies the predicate above, the column is zero on illegitimate episodes by construction: every publish is an unsafe attempt, and a corrected summary stays inside that attempt count. The descriptive name for this difference is \texttt{publish\_\allowbreak{}decisions\_\allowbreak{}without\_\allowbreak{}unsafe\_\allowbreak{}attempt}.

Family-cluster bootstrap uses the four \texttt{family\_\allowbreak{}id} blocks in a split, with percentile intervals and paired arm contrasts inside each model and each coordination stratum. The ten variants are not resampling units. Models and coordination conditions are not pooled. Marginal bootstrap intervals resample available completed cases within each arm. Paired contrasts instead require all four arms to have completed endpoint-eligible episodes with identical fixture-ID sets in a family, so they can exclude families that still contribute to marginal rates. \texttt{scripts/prepare\_\allowbreak{}live\_\allowbreak{}paper.py} pulls aggregates only from supplied analysis outputs. It does not invent counts.

\section{Discussion}
Arms that lack provenance remain advisory: a supervisor publish decision still executes on the fake sink unless the provenance gate vetoes the request. That veto is deterministic code, not a supervisor decision to block. State can approve internally consistent keeper bodies without seeing trusted inputs committed off-keeper. That is a coverage limit, not evidence that adaptive querying was tested. Single versus coordinated conditions differ in message count and speaker roles, and honest controls exist only as three-speaker pipelines, so coordination contrasts are descriptive. The assembled worker corpus reproduces the scripted baseline on all 280 accepted calls. Those messages are one-shot wording under adversarial instructions. They are not emergent collusion. Bootstrap intervals resample four family blocks that implement three mechanisms, with consistent fake input on two blocks, and stay coarse.
